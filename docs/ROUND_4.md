# LIVERA Round 4 — คำขอบริการส่วนตัว

## ขอบเขต

เพิ่มบริการส่วนตัวตามแผนเดิม โดยยังเป็นต้นแบบข้อมูลสมมติในเบราว์เซอร์ ไม่มีการส่งข้อมูลไปถึงผู้ให้บริการหรือบริษัทประกัน ไม่มีธุรกรรม และไม่มีการรักษา/วินิจฉัยจริง

### นัดปรึกษาสุขภาพกายและใจ

- เลือกสุขภาพกายหรือใจ สาขา และหัวข้อทั่วไป รูปแบบออนไลน์หรือพบกันจริง
- สาขาเป็นประเภทผู้ให้บริการ ไม่สร้างชื่อแพทย์ เลขใบประกอบวิชาชีพ โรงพยาบาล หรือคู่ค้าที่ไม่มีข้อมูลจริง
- ระบุว่านักจิตวิทยาเป็นผู้เชี่ยวชาญที่ไม่ใช่แพทย์ แยกจากตัวเลือกจิตแพทย์
- หัวข้อเป็นตัวเลือก ไม่มีช่องเขียนอาการหรือประวัติรักษา และไม่มีการแนบเอกสารสุขภาพ
- เลือกเวลาที่สะดวก 1–2 ช่วง ตั้งแต่พรุ่งนี้ถึง 90 วันข้างหน้า ตามวันที่ประเทศไทย ช่วงสำรองต้องไม่ซ้ำ
- เวลาที่เลือกเป็นความสะดวกของสมาชิก ไม่ใช่ตารางว่างของผู้ให้บริการ
- ช่องทางติดต่อเป็น enum ตัวอย่าง: ในแอป เบอร์ปกปิด และอีเมล example.invalid ไม่มีการกรอก/ส่งข้อมูลติดต่อจริง
- ความยินยอมแยกสำหรับการประสานนัดและการใช้ข้อมูลตัวอย่าง ตรวจสรุปก่อนกดบันทึก
- เก็บคำขอและประวัติหลังรีเฟรช แก้ข้อมูล/ช่วงเวลาและยกเลิกคำขอได้
- เมื่อแก้หลังเสนอหรือยืนยันนัด ล้างเวลาเสนอเดิมและเริ่มขั้นตอนสาธิตใหม่ พร้อมขอความยินยอมอีกครั้ง

### ทบทวนความคุ้มครอง

- เลือกเป้าหมายสุขภาพ รายรับเกษียณ หรือครอบครัว และงบตัวอย่าง
- ข้อมูลสุขภาพเลือกเองจากตัวเลือกสมมติ เช่น เบาหวาน ไม่มีการอ่านจากคำขอปรึกษาสุขภาพ
- เลือกแผน LIVERA ประกอบได้ เฉพาะชื่อและประเภท ไม่รวมยอดเงิน ไฟล์หลักฐาน หรือประวัติปรึกษา
- ความยินยอมสำหรับวัตถุประสงค์ทบทวน การใช้ข้อมูลสุขภาพ และการใช้ชื่อแผน แยกกันตามตัวเลือกที่ใช้
- ไม่อนุมานว่าสมัครประกันได้ ไม่จัดอันดับความเหมาะสมจากโรค และไม่แสดงข้อเสนอประกันที่ไม่มีข้อมูลคู่ค้ารองรับ
- ผลสาธิตเป็นหัวข้อที่เลือกไว้คุยต่อ: สิ่งที่อยากคุ้มครอง งบ เงื่อนไข ข้อยกเว้น ระยะรอ และข้อมูลที่ควรให้ผู้รับผิดชอบอธิบาย
- ไม่มีการสมัคร ซื้อ รับประกันผลพิจารณา หรือรับรองความคุ้มครองโรคที่เลือก

## สถานะและการจำลอง

เริ่มที่ `recorded` — บันทึกคำขอสาธิตเท่านั้น

หน้ารายละเอียดมีส่วนพับ “ทดลองสถานะคำขอ · สาธิต” ผู้ใช้กดดูขั้นตอนเอง ไม่มีเจ้าหน้าที่หรือการเปลี่ยนสถานะเบื้องหลังจริง:

1. `recorded` → `coordinating`: จำลองการประสานงาน
2. คำขอนัด: `coordinating` → `proposed`: เสนอเวลาตัวอย่างจากช่วงแรกที่เลือก และราคา *สมมติ* 900 บาทสำหรับสุขภาพกาย / 1,200 บาทสำหรับสุขภาพใจ ระยะเวลาสมมติ 30 นาที ตัวเลขนี้กำหนดเพื่อทดสอบ UI ไม่ใช่ราคาจากแหล่งภายนอกหรือผู้ให้บริการ
3. ผู้ใช้ตรวจราคา/เวลาและยืนยันความเข้าใจเรื่องข้อมูลสาธิตแยกกัน จึงเปลี่ยน `proposed` → `confirmed` ไม่มีการรับเงินจริงหรือยืนยันกับบุคลากร
4. หลังยืนยันสามารถกดจำลองจบนัด → `completed` ไม่ได้มีการให้คำปรึกษาหรือรักษาจริง
5. คำขอทบทวน: `coordinating` → `review-ready` แสดงหัวข้อที่สร้างจากตัวเลือก จากนั้นผู้ใช้ทำเครื่องหมายอ่านแล้ว → `completed`
6. ยกเลิกคำขอที่ยังไม่จบ → `cancelled` เก็บประวัติไว้ ไม่มีการส่งเรื่องยกเลิกจริง

ตรวจเวลาเสนอที่ผ่านไปแล้ว และห้ามยืนยันนัดสาธิตซ้อนกับนัดอื่นที่ยืนยันไว้ การยืนยันราคาใช้ snapshot พร้อม revision เพื่อไม่ยอมรับข้อเสนอที่เปลี่ยนจากอีกแท็บโดยไม่ตรวจใหม่

## การจัดเก็บและการแยกข้อมูล

- IndexedDB `livera-round4-services`, store `state` แยกจากเบี้ย แผนเงิน และคลับ
- อ่าน ตรวจข้อมูล ตรวจ revision/รายการซ้ำ และเขียนใน readwrite transaction เดียว
- ประวัติเก็บ actor ว่าเป็นสมาชิกหรือระบบจำลอง ไม่อ้างว่าเจ้าหน้าที่หรือแพทย์ดำเนินการแล้ว
- ข้อมูลเข้าใช้ whitelist ของ structured fields ไม่เก็บ clinical notes หรือไฟล์ที่อาจแทรกมา
- บังคับ revision ป้องกันการแก้ทับ ยกเลิก หรือยืนยันจากหน้าเก่า
- ป้องกันกดซ้ำระหว่างเขียน และแจ้งผิดพลาดโดยไม่อ้างว่าบันทึกสำเร็จ
- ข้อมูลผิดรูปแบบไม่ถูกเขียนทับด้วยข้อมูลตั้งต้นเงียบ ๆ มีลองโหลดและล้างคำขอบริการแยกพร้อมหน้าตรวจยืนยัน
- ไม่มีร่างอัตโนมัติสำหรับคำขอส่วนตัว ต้องกดบันทึกจึงเก็บข้อมูล
- BroadcastChannel/focus refresh ใช้อัปเดตระหว่างแท็บเบราว์เซอร์เดียวกัน ไม่ซิงก์ข้ามอุปกรณ์
- เมื่อเปิดซ่อนยอด แอปซ่อนทั้งฟอร์มและรายละเอียดบริการที่มีงบ/ค่าบริการก่อนแสดง
- ไม่มีการส่งข้อมูลไป Community หรือใช้เพื่อการตลาดอัตโนมัติ

## หน้าจอ

- สำรวจบริการ พร้อมภาพสมจริงจาก asset เดิมและป้าย AI
- ฟอร์ม 3 ขั้นแยกประเภทบริการ พร้อมหน้าตรวจสรุป
- รายการคำขอ ค้นหาด้วยประเภท/รหัส กรองประเภทและสถานะ
- รายละเอียดคำขอ เวลา/ค่าบริการสมมติ และ timeline
- Modal แก้ไข ยกเลิก ยืนยันข้อเสนอ ล้างข้อมูล และคำอธิบายวัตถุประสงค์ข้อมูล
- โหลดหน้าบริการแยกเป็น JavaScript chunk เพื่อลดภาระเริ่มแอป
- รักษาเมนูข่าว/คลิปสำหรับรอบ 5 และบ้านพักสำหรับแนวทางถัดไป

## ตรวจสอบ

Unit tests รวม 64 กรณี: 45 เดิม + 19 กติกาบริการ ได้แก่ วันที่ประเทศไทย วันพรุ่งนี้/90 วัน ช่วงสำรองซ้ำ ประเภทสาขา ความยินยอมแยก ข้อมูล whitelist รายการซ้ำ สถานะ ค่าบริการสมมติ เวลาเลยกำหนด นัดซ้อน การเลื่อนนัด รุ่นข้อมูลเก่า และหัวข้อทบทวน

UI ที่ตรวจ:

- เลือกสุขภาพใจ → นักจิตวิทยา → เวลาและช่องทาง → ความยินยอม → สรุป → บันทึก → รีเฟรช
- จำลองประสานและเวลาเสนอ ตรวจค่าตัวอย่าง 1,200 บาท ยืนยันไม่ได้หากไม่รับทราบราคา/ความเป็นสาธิต
- แก้ช่วงเวลาหลังยืนยัน ขอความยินยอมใหม่ ล้าง proposal กลับเป็นบันทึกคำขอ และเก็บประวัติเดิม
- เลือกงบ ข้อมูลเบาหวานสมมติ และชื่อแผนสุขภาพ ต้องยืนยันสุขภาพและชื่อกรมธรรม์แยกจาก purpose/demo consent
- จำลองหัวข้อทบทวน ทำเครื่องหมายอ่านแล้ว และรีเฟรชแล้วยังจบรายการ
- ยกเลิกคำขอ และยังเห็นประวัติในรายการของฉัน
- หน้าบริการ ฟอร์มทั้งสอง รายการ และรายละเอียดทั้งสอง ไม่ล้นที่ 360px ทั้งขนาดปกติและตัวอักษรใหญ่ 19px
- โหมดซ่อนยอดไม่แสดง input หรือ summary ของคำขอ

## บริบทที่ตรวจจากแหล่งข้อมูล

ตรวจ 11 พฤศจิกายน 2569 เพื่อประกอบการออกแบบขอบเขต ไม่ใช้เป็นราคา/เงื่อนไขสินค้า หรือการรับรองว่าต้นแบบพร้อมให้บริการจริง:

- สำนักงานคณะกรรมการสุขภาพแห่งชาติ — ภาพรวม telemedicine และประเด็นความยินยอม/ความปลอดภัย: https://www.nationalhealth.or.th/public/index.php/articles/th/84
- บริษัทประกันอธิบายว่าการมีโรคประจำตัวอาจเกี่ยวข้องกับเงื่อนไขรับประกัน: https://www.aia.co.th/th/our-products/health-benefit-protection — ไม่ได้นำชื่อผลิตภัณฑ์หรือความเห็นพิจารณามาใส่ในแอป

ระบบให้บริการจริงยังต้องมีคู่ค้าบุคลากร รายชื่อและสิทธิที่ตรวจสอบได้ ค่าบริการจริง ระบบสมาชิกและการควบคุมสิทธิ์ฝั่งเซิร์ฟเวอร์ ช่องทางประสานงานจริง และการจัดการข้อมูลที่เหมาะสม รอบนี้ยังเป็นต้นแบบเท่านั้น

ตรวจเพิ่ม: ล้างคำขอบริการแล้วเหลือ 0 คำขอ ข้อมูลสรุปเบี้ยก่อน/หลังตรงกัน และจำนวนกระทู้ Community เท่าเดิม ไม่พบ warning/error ใน console ของแท็บที่ตรวจ
